# 技术适配声明

> 项目：中国艺术史时空地图
> 日期：2026-09-23
> 依据：《中国艺术史时空地图_PRD.md》v0.1 + 《通用技术栈手册》第一至六节

## 1. 产品形态判断

- **产品类型与核心任务**：可视化内容产品（非 AI Agent）。用「时间 × 空间」双轴叙事，让用户在地图上拖动朝代时间轴，直观看懂「中国美术中心为什么一路往南走」。核心任务是**朝代切换 → 地图气泡/轨迹线可视化 → 详情叙事**。
- **核心交互**：其他（纯前端交互可视化，非生成类）。主链路是：进入页面默认「唐」→ 拖时间轴 → 气泡按新朝代过渡 + 轨迹线生长 → 侧栏叙事同步 → 点气泡看详情面板。
- **开发路径**：**纵向切片**（本产品没有后端，交互/地图可视化本身就是产品核心，不存在"后端能力先行"）。
- **当前阶段范围**：MVP v0.1 = F01–F09（P0 全部）＋ F10（P1，画家索引，数据已在模型内，成本低故纳入）。F11/F12（P1）、F13/F14（P2）不在本阶段。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| 前端框架 React + TypeScript | PRD 7.1 明确指定；时间轴为全局状态，组件化 + 类型约束可防数据录入错误 |
| 构建工具 Vite | PRD 指定；冷启动快，纯静态无 SSR 需求 |
| 地图 百度地图 JSAPI GL v1.0 | PRD 指定；WebGL 渲染、个性化底图、免费无调用次数限制 |
| 数据 静态 JSON 随包发布 | 数据量 < 200KB，无后端/数据库需求（PRD 4.2/7.1） |
| 部署 腾讯云 EdgeOne Pages | 静态托管，国内访问快；账号已实名 |
| 状态管理 React useState | 核心状态仅 currentDynasty 一个（PRD 7.1） |

## 3. 触发的按需模块

- 无。不引入任何按需模块（数据库、RAG、OCR、任务队列、对象存储、SSE 均不触发）。

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 后端 Python + FastAPI | 无后端 | MVP 为纯前端可视化，无模型调用/数据库/登录 | 偏离默认，但符合 PRD 4.2 明确"不做后端" | F13 AI 讲解、F11/F14 需服务端 POI 检索代理时，再评估引入轻后端 |
| 数据库 SQLite/SQLAlchemy | 静态 JSON 文件 | 数据量小、只读、无并发写 | 无持久化任务/用户数据 | 出现用户系统、收藏、多用户写时再引入 |
| Web 默认栈 Next.js | Vite + React SPA | PRD 指定 React+Vite；纯静态无 SSR/SEO 刚需 | 分享落地页无 SSR 预渲染 | 若需 SEO/服务端渲染再评估 |
| 模型调用 | 无 | MVP 无 AI 生成（F13 为 P2） | 无真实模型冒烟项 | v1 引入 AI 讲解时定模型与成本 |

## 5. 强制底线检查

| 检查项 | 状态 | 说明 |
| --- | --- | --- |
| 密钥与隐私 | 通过 | 百度 AK 为 Web 端公开 AK，控制台配 Referer 白名单防盗用；AK 存 .env 不入仓库、不回显；严禁服务端 AK 入前端 |
| 数据与任务可恢复 | 通过 | 静态数据随包发布，无用户数据、无任务状态需持久化；数据 JSON 走 Git 版本管理可回溯 |
| 输入输出校验 | 通过 | 构建/加载时校验 JSON schema：coordSystem 必须 BD09、weight∈[0,1]、type∈{宫廷,文人,宗教,市民}、narrative 80–120 字 |
| 错误与日志边界 | 通过 | 埋点只采 PV/UV、切换次数、点击率、停留时长，不采个人信息；日志不记密钥 |
| 测试与真实模型验收 | 计划 | 无真实模型。验收 = 数据 schema 校验自动化测试 + 浏览器人工冒烟（地图加载/朝代切换/气泡渲染/轨迹线/详情面板），无 Key 依赖 |
